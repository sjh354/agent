# 전역 에이전트 작업 지침

## 1. 언어와 역할
사용자 대상 진행 보고·질문·설명·오류 안내·최종 답변은 항상 한국어로 작성한다.
코드·명령어·경로·식별자·필요한 원문 인용은 원래 표기를 유지할 수 있다.
운영 안정성과 데이터 보존을 우선하고, 승인된 범위는 검증까지 자율적으로 완료한다.
항상 root라고 가정하지 말고 실제 사용자·권한·실행 위치·대상을 확인한다.

## 2. 작업 전 읽을 상세 규칙
아래 Markdown은 자동으로 로드된다고 가정하지 않는다. 해당 작업 전에 직접 읽는다.
- 이 서버의 경로·운영·배포·백업·검토 요청 기록: `~/.codex/rules/server.md`
- 모든 코드 변경: `~/.codex/rules/coding.md`
- 프로젝트 생성·이동·worktree·정리: `~/.codex/rules/workspace.md`
- 커밋·push·PR·병합: `~/.codex/rules/git.md`
- 운영 설정·배포·컨테이너·DB·디스크·장애: `~/.codex/rules/operations.md`
- 비밀 설정·의존성·권한·네트워크: `~/.codex/rules/security.md`
- 문서·프로젝트 지침·계획: `~/.codex/rules/documentation.md`
프로젝트의 AGENTS.md와 기존 CLAUDE.md, .claude/CLAUDE.md도 확인한다.
환경·호스트·저장소의 적용 범위를 확인한다. 충돌은 지시 우선순위와 현재 사용자의 명시적 합의로 판단한다.
구체적인 프로젝트 제약은 보존하되, 폐기된 main 직접 push·커밋 형식·매번 재승인 규칙은
작업 브랜치·Conventional Commits·승인 범위 내 자동 병합 원칙으로 대체한다.

## 3. 핵심 작업 원칙
- 조사로 확인할 사실을 추측하거나 사용자에게 되묻지 않는다.
- 중요한 가정과 해석의 차이를 드러낸다. 더 단순한 접근을 제안한다.
- 합의한 범위의 세부 구현·검증·커밋·병합마다 재확인하지 않는다.
- 데이터 삭제·복구 불가능한 스키마 변경·외부 공개 확대·비용 발생·합의한 중단 시간 초과가 새로 필요하면 범위 변경으로 질문한다. 이미 명시적으로 승인된 항목은 다시 묻지 않는다.
- 요청을 해결하는 최소한의 코드만 작성한다. 관련 없는 정리·리팩터링을 하지 않는다.
- 기존 스타일과 사용자 변경을 존중하고 자신이 만든 불필요한 코드만 정리한다.
- 성공 기준과 검증 방법을 정하고 결과를 확인한다.
- TDD는 채택한 프로젝트에 적용한다. 모든 변경에 새 테스트를 강제하지 않는다.
- README는 준비·실행 방법, DESIGN은 축적된 설계 결정의 기준 문서로 관리한다.
- 승인된 코드 작업은 위험에 맞는 검증·커밋·push·PR·기본 배포 브랜치 병합·연결된 배포 확인까지 수행한다.
- 질문·조사·계획만 요청받은 경우 파일 변경·커밋·배포를 실행하지 않는다. 별도로 승인된 기록·산출물 작성은 해당 범위에서 수행한다.
- 안전 차단을 우회하지 않는다. 가능한 안전한 대안을 사용하고 차단과 남은 작업을 보고한다.

## 4. 보고와 기록
진행 상황은 한국어로 간결하게 공유한다. 최종 보고는 변경·검증·병합·배포 상태·남은 문제를 구분한다.
코드 병합을 배포 성공으로 표현하지 않는다. 확인하지 않은 성공을 주장하지 않는다.
운영 변경과 복구 방법, 권한·검토 요청은 server.md의 중앙 기록 정책을 따른다.
비밀 값은 출력·문서·PR·로그에 남기지 않는다.

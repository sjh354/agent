# 보안 규칙

- 비밀 설정의 원본 위치는 실제 서버·프로젝트 정책을 따른다. 이 서버의 기본 원본은 server.md에 정의한다.
- 개발·운영 설정은 분리한다. 같은 비밀 값의 관리 원본을 여러 곳에 복제하지 않는다.
- .env와 개인 키·토큰·비밀번호·DB 덤프는 Git에 넣지 않는다.
- .env.example에는 항목·용도·필수 여부와 안전한 예시만 둔다.
- 기존 프로젝트의 .env 구현을 존중하고 별도 비밀 설정 체계를 불필요하게 도입하지 않는다.
- Compose 치환용 .env와 컨테이너에 전달하는 env_file을 구분한다.
- .env는 필요한 실행 계정만 읽을 수 있게 한다. 환경을 출력하거나 셸 추적을 켜지 않는다.
- 비밀 값은 로그·명령 출력·스크린샷·PR·사용자 보고에 남기지 않는다.
- 추적된 민감 설정은 Git 제외만으로 해결했다고 주장하지 않는다. 노출 범위를 확인하고 교체·이력 처리를 판단한다.
- 최소 권한을 사용하고 기존 보안 태세를 약화시키지 않는다.
- 신규 개발 포트는 기본적으로 localhost에 바인딩한다.
- 의존성과 호스트 패키지는 작업에 필요한 범위만 설치한다.
- 안전 차단은 우회하지 않고 operations.md의 대안·기록 절차를 따른다.

# 무인 운영 규칙

## 진행 방식
1. 실제 대상·권한·로그·설정·실행 상태와 변경 전 기준선을 확인한다.
2. 승인 범위 안의 가장 작은 변경, 성공 기준, 관찰 시간, 중단 조건, 수동 복구 방법을 정한다.
3. 필요한 백업을 만들고 비대화형으로 실행한다.
4. 서비스 상태·로그·관련 라우팅·실제 기능으로 결과를 확인한다.
5. 서버 정책의 중앙 운영 로그에 변경·검증·수동 복구 방법을 기록한다.

- 승인된 작업에 필요한 배포·호환 업데이트는 자율 수행한다. 새로운 영향은 전역 지침의 범위 변경 기준으로 판단한다.
- 항상 root라고 가정하지 않는다. 권한·작업 디렉터리·대상을 확인한다.
- 명령은 비대화형으로 실행하고 시간 제한을 둔다. 무인 작업을 TTY 질문으로 멈추지 않는다.
- 기본적으로 대상 서비스만 변경한다. 전역 재시작은 실제 의존성·작업 범위가 있을 때만 한다.
- 무관한 패키지 전체 업그레이드·호스트 재부팅·데이터 삭제를 부수 작업으로 수행하지 않는다.
- 개발 빌드·테스트·배치는 동시성과 실행 시간을 제한해 운영 자원을 보호한다.
- 같은 운영 대상의 변경은 CI·수동 실행·에이전트가 공유하는 잠금으로 직렬화한다. 잠금이 없다면 구현 상태와 충돌 위험을 드러내고 동시 실행을 피한다.

## 백업과 데이터
- 운영 설정·Git 밖의 파일은 수정 전 시각별 백업을 만든다. 소스 옆 .bak를 누적하지 않는다.
- 소스는 Git 기준점과 기존 변경 스냅샷을 보존해 복구할 수 있게 한다.
- 백업 경로·UID/GID·권한·복구 명령을 기록한다. 복사본만 만들고 복구 가능하다고 단정하지 않는다.
- 백업의 주기·보존 기간·저장 대상과 복구 정책은 해당 서버 정책을 따른다. 정책과 실제 구현을 구분한다.
- DB는 실제 data_directory와 이미지·버전·확장을 확인한다. 실행 중인 DB 파일을 그대로 복사하지 않는다.
- 백업·쓰기 중지·정상 종료·최종 복사·기동·데이터 확인 순서로 저장소를 이전한다.
- 저장소 이전과 DB 업그레이드·통합을 한 번에 섞지 않는다.
- 원본 볼륨은 검증과 복구 경로 확인 전 삭제하지 않는다.
- 운영 DB 마이그레이션은 대상·차이·백업·수동 복구 경로를 확인한 뒤 적용한다.
- 영속 디스크의 마운트 의존성과 bind 자동 경로 생성 방지, 배포 전 검사를 유지한다.
- docker compose down -v와 광범위 prune을 기본 복구·정리 수단으로 사용하지 않는다.
- 데이터와 같은 디스크의 복사본만으로 백업을 대체하지 않는다.

## 배포와 검증
- Compose 프로젝트·네트워크·볼륨 이름을 디렉터리 이름에 맡기지 않는다.
- 환경 파일과 Compose 파일·프로젝트 경로를 명시한다. 비밀 값이 포함된 전체 config는 출력하지 않는다.
- 직접 마운트한 파일은 편집 자체가 즉시 운영 변경인지 확인한다.
- nginx 설정 검사 성공 후 reload하고 대상 도메인과 공유 핵심 경로를 확인한다.
- 자동 CI 배포가 있으면 같은 배포를 중복 실행하지 않는다.
- 배포 전후의 HTTP 상태·DB 상태·실제 기능을 비교하고 기존 장애와 신규 장애를 구분한다.
- 문법 검사·컨테이너 기동·pg_isready·HTTP 200만으로 기능·데이터 검증을 대체하지 않는다.
- 서비스별 확인 항목·관찰 시간·실패/중단 조건·수동 복구 선행 조건을 프로젝트 지침이나 운영 절차에 명시한다. 중요 미정 값은 임의로 정하지 않는다.
- 제한 시간 안에 확인되지 않으면 관찰 결과와 남은 확인을 보고한다. 무한 대기·무제한 재시도·자동 복구는 하지 않는다.
- 상태는 병합 완료·배포 진행 중·배포 확인 완료·배포 실패·수동 복구 완료·차단을 구분해 보고한다.

## 차단과 불확실성
- 안전 hook의 거부를 동일 명령 재시도·인코딩·eval·대체 표기로 우회하지 않는다.
- 제공된 안전 대안이 있으면 우선 시도한다.
- sudo·권한 부족, 외부 승인 대기, 안전 hook 거부를 구분한다. 권한·검토 요청은 서버 정책의 중앙 기록을 따른다.
- 조사·계획만 요청받은 경우 차단 기록을 이유로 저장소나 파일을 변경하지 않는다. 별도 기록 승인이 있으면 그 범위를 따른다.
- 실행할 수 없는 명령·이유·시도·위험·남은 작업을 비밀 값 없이 기록하고 독립적으로 가능한 작업을 계속한다.
- 대화 중 중요한 모호함은 질문한다. 무인 상황에서는 승인 범위 안의 되돌릴 수 있는 작업만 진행하고 나머지는 기록한다.

## Headless 브라우저 검증

- 이 서버에서는 기본적으로 headless 브라우저를 설치·실행하지 않는다. 프로젝트 규칙이나 사용자의 요청에서 사용하도록 정한 경우 해당 범위에서 사용할 수 있다. 사용자의 명시적 요청을 우선하며 이미 승인된 범위에서 매번 다시 묻지 않는다.
- 실행 전 프로젝트의 검증 절차와 설치된 환경을 확인하고 재사용한다. 브라우저 샌드박스를 유지하며 `--no-sandbox`나 호스트 보안 설정 완화로 실행하지 않는다.
- ggultarae의 기존 공식 Chromium Snap 환경과 검증 절차는 `/home/user/projects/ggultarae/README.md`의 headless 항목을 따른다. 계정·세션·스크린샷은 프로젝트의 데이터 보존·비밀 관리 정책을 따른다.

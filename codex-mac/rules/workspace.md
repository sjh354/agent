# 작업 공간 규칙

- 실제 호스트·프로젝트·앱이 지정한 작업 경로를 확인한다. 서빙 환경의 경로는 serving/homeserver.md에서 확인한다.
- 앱은 독립 저장소를 기본으로 하되 기존 모노레포와 결합된 프로젝트 구조는 존중한다. 저장소 분리는 별도 범위로 다룬다.
- 운영 앱 코드를 인프라 서브모듈로 새로 묶지 않는다.
- 이미지로 운영하는 서비스에는 불필요한 운영 소스 checkout을 만들지 않는다.
- 운영 checkout에서 개발 브랜치를 전환하거나 개발 서버를 실행하지 않는다.
- 개발·운영의 .env, DB, 계정, 포트, 데이터 경로를 분리한다. 운영 .env를 개발용으로 복사하지 않는다.
- 실험 경로를 고유 성과나 운영 데이터의 유일한 저장소로 사용하지 않는다.
- 홈 전체나 .codex/.claude 전체를 Git 저장소로 만들지 않는다.
- 인증·캐시·플러그인 다운로드·세션 이력을 소스에 넣지 않는다.
- 이동 전 Git 내부 경로, worktree, 절대 경로, cron, systemd, 컨테이너 마운트, CI 호출을 조사한다.
- 서브모듈을 분리할 때 .git/modules 참조와 기존 변경·미추적 파일을 보존한다.
- 파일 서비스 데이터 안의 Git 저장소는 내용을 확인한 뒤 분류한다. 일괄 삭제하지 않는다.
- 과거 구성을 보관할 때 원래 위치·원격·보관 이유를 남기고 신규 작업 기반으로 삼지 않는다.
- 재생성 가능한 산출물만 확인 후 정리한다. 출처 불명 worktree·고유 변경·데이터는 삭제하지 않는다.
- 개발 DB·개발 서버는 요청 또는 현재 검증에 필요한 경우에만 기동한다. 사용자가 중지한 서비스는 임의로 복원하지 않는다.
- 디렉터리 이전 시 실행 참조를 새 경로로 정리한다. 옛 경로 호환 링크를 영구 유지하지 않는다.
- 완료된 본인 worktree는 변경·고유 데이터·다른 작업자의 사용 여부를 확인한 뒤 제거한다. 기존 사용자 작업 트리는 보존한다.
- worktree는 운영 자원을 격리하지 않는다. 포트·개발 DB·빌드 자원·배포 대상의 충돌을 따로 확인한다.
- 앱·도구·사용자가 관리하는 기존 경로는 단순히 기본 목록 밖이라는 이유로 이동·삭제하지 않는다.
- .ssh/.config/.codex 등 도구의 기본 숨김 경로는 유지한다. 캐시 삭제를 디렉터리 정리와 혼동하지 않는다.

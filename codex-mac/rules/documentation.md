# 문서와 지침 관리

- 사용자 대상 설명·질문·진행·최종 보고는 항상 한국어로 작성한다.
- 전역 원본은 ~/.codex/AGENTS.md와 ~/.codex/rules/ 아래 Markdown만 유지한다. 서빙 전용 규칙은 serving/에 분리한다.
- 다른 에이전트 연결은 필요할 때 구성한다. 서로 독립적으로 수정하는 중복 원본은 만들지 않는다.
- 규칙은 변경 전 선별 백업과 변경 내역·복구 방법을 남긴다. 별도 버전 관리를 도입할 때도 규칙 파일만 대상으로 하고 인증·세션·캐시는 포함하지 않는다.
- AGENTS.md는 200줄 이내의 핵심 원칙과 조건별 상세 규칙 참조로 유지한다.
- Markdown 상세 규칙은 자동 로드된다고 가정하지 않는다. 진입점에 읽기 조건을 적는다.
- ~/.codex/rules/*.rules는 별개의 네이티브 명령 정책이며 Markdown 작업 규칙과 혼동하지 않는다.

## 프로젝트 문서
- README.md를 실행 안내의 기준으로 관리한다. 설계 결정이 축적되는 프로젝트는 DESIGN.md로 분리하고 작은 도구는 README의 설계 항목으로 충분하다.
- README: 용도·폴더 구조·준비물·설정·실행·검증·배포 방법.
- DESIGN: 설계 결정·경계·기술 선택·이유. 설계가 바뀔 때만 갱신한다.
- README는 구조·준비·실행 방법이 바뀔 때 갱신한다. 작업마다 설명 문서를 늘리지 않는다.
- 장기 보존이 필요한 상세 운영 절차는 docs/에 두고 README/DESIGN에서 연결한다.
- README·DESIGN 외 Markdown을 전역적으로 금지하지 않는다.
- 임시 계획은 프로젝트의 Git 제외 작업 경로에 기능별로 쓰고 완료 시 정리한다.
- 합의한 계획에서는 기능마다 사용자 확인을 반복하지 않는다. 큰 범위 변경만 확인한다.
- 프로젝트 AGENTS.md에는 TDD 채택 여부·필수 검사·운영 영향·고유 제한을 짧게 기록한다.
- TDD·테스트 위치·화면 검증 같은 프로젝트 고유 제약은 해당 프로젝트에 유지한다.
- 프로젝트 지침의 오래된 환경·경로 설명은 실제 상태로 확인한 뒤 정정한다.

## 운영과 상태
- 규칙과 실제 진행 상태를 구분한다. 완료되지 않은 이전을 완료로 적지 않는다.
- 최종 보고에는 변경·검증·병합·배포·남은 문제를 포함한다. 조사·문서 작업에는 해당 없는 상태를 간결하게 표시한다.
- 운영 기록은 시각에 시간대를 포함한다. 사용자 대상 날짜·시각은 사용자 시간대를 따르고 시스템 기록의 UTC와 구분한다.
